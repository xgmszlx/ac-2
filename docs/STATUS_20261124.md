### 1.4 Gazebo 环境打通（这一段踩了最多坑，结论可复用）

本机现状：Ubuntu 20.04 + Noetic + Gazebo 11 + RTX 4060(515/535) + Intel iGPU，用户无 sudo。

实测结论（每条都有 A/B 日志）：

1. **OpenGL 正常**：自写 GLX 探针 `tools/gltest` 三种配置全部可用
   （Intel GL 4.6 / llvmpipe 3.1 / NVIDIA 535 GL 4.6）。所以渲染能力不是问题。
2. **作者的 kobuki URDF 在本机 Gazebo 11 上传感器永远不发布**：`/base_scan` 连 topic 都不注册，
   相机 topic 注册了但没有一帧图像（`gpu_ray` + `type="depth"` 相机，`<updateRate>1.0</updateRate>`）。
   改 `<always_on>`、加 `<depth_camera/>`、把 gpu_ray 换 CPU ray **都没救活**。
3. **AWS world 的 `<physics default="0" name="default_physics">` 会让 spawn 出来的机器人传感器全部静默**：
   `/clock` 照常 1.0 倍实时推进、物理在跑、`pause: False`，但所有传感器零帧。
   （这正是 500 多行 parser 警告之后"一切正常却没图像"的原因）
4. 用**可用的机器人**（本机已装的 TurtleBot3 Waffle，同为差速+RGB-D）替换 kobuki 后，
   在重建的 world 上相机 820 帧/9 s、深度 818、激光 40、里程计 239 —— 全活。
5. **段错误（libtinyxml）只在"spawn 机器人 + 同时有很多其他节点在启动"时出现**；
   单独启动 `sim_house.launch`（含 move_base + ORB-SLAM）稳定不崩。

## 2 方法：已实现的部分（代码已进工作区，尚未出数）

思路严格按任务书，且**不改前端、不改检测器、不改候选池、不改运动约束**：

| 任务书要求 | 实现位置 | 关键设计 |
|---|---|---|
| 可执行候选路径采样未来位姿+到达时间 | `decision_maker/src/python/loo_observability.py::PathSampler` | 直接用 `move_base` 的 `make_plan` 结果（作者 hallucinate 时**本来就会调**，我们只是把同一份 plan 存下来，不额外规划），按 0.45 m 采样，用梯形速度曲线算到达时刻 τ |
| 统一平移/旋转尺度的几何可观性 | 同上 `ObservabilityEstimator` | 每点位姿累加 6×6 FIM（Jacobian 形式与作者 `hallucinateHessianFromPose` 一致），用 `Σ=diag(σ_t,σ_t,σ_t,σ_r,σ_r,σ_r)` 归一化后取**最弱方向** `1/max_i(C_ii/s_i²)`；**不用特征数量代替几何可观性** |
| 历史观测做自运动补偿+短期动态预测 | `loo_occlusion.py::OcclusionField` | 用前端**已经在发**的两个量：`n_real(k)`（该关键帧真正匹配上的地图点数，来自 `point_list` 的共视集合）与 `n_exp(k)`（当前地图几何上应可见的点数）。比值就是**实测遮挡率**，且天然按视角条件化；在 (x,y,yaw,t) 上做核平滑 + Beta 后验，规划器吃**上置信界**（不确定性进代价） |
| 未知区域的新特征先验 | `loo_occlusion.py::ExplorationCredit` | 用 frontier 检测器同一张栅格图，算未来视锥内未知格比例 ρ，用 `(1-ρ)^γ` 折扣亏空，避免"只保护旧地图点" |
| 有界"信息不足程度+持续时间"代价 | `loo_planner.py::LOOScorer` | `W=Σ_k g(d_k)·Δτ_k`，`d_k=clip(log(ref/strength_eff),0,cap)·(1-ρ)^γ`；`ref` 取当前环境关键帧强度的滑动分位数（**不需要人为标定前端的绝对阈值**） |
| 基线拿到同一候选池 | `Controller.py` 的 `~strategy` 开关 | `native`=作者原样；另有 `travel_only`（只加旅行代价，用于剥离"是不是只是走得少"）、`loo_full`、`loo_notemporal`、`loo_noduration`（两个消融）——**同一段候选生成、同一份 plan 采样、同一套运动约束，只有打分不同** |

`decisions.csv`（每个候选每次决策的 gain/T/W/score/遮挡率/亏空）是"实际动作日志"的规划侧证据。
